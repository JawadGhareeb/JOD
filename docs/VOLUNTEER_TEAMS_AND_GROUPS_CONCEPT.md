# JOD — المفهوم النهائي للفرق التطوعية

## الفكرة

الميزة عبارة عن **فرق تطوعية عامة** داخل JOD تجمع المستخدمين حول هدف تطوعي أو اجتماعي واضح، مع أعضاء وأدوار ومنشورات وتفاعل وإمكانية إضافة مهام تشغيلية مستقبلًا.

يوجد نوع واحد فقط للمستخدم: **فريق تطوعي**.

اسم `Group` أو جدول `groups` هو تفصيل تقني داخلي وليس نوعًا ثانيًا في المنتج.

## ما لا يوجد في المنتج

لا يوجد:

```text
community
kind
volunteer_team كنوع منفصل
visibility
public/private selector
private teams
invite-only teams
join requests
join approval
```

كل فريق توافق عليه إدارة JOD يصبح عامًا.

## إنشاء الفريق

المستخدم المسجل يرسل:

- الاسم.
- الوصف.
- التصنيف.
- الموقع.
- القواعد.
- سبب الإنشاء.
- صورة اختيارية.
- مشرفين مقترحين اختياريًا.

المنشئ يصبح `owner`، والحالة تبدأ `pending`.

إدارة JOD:

- توافق → `active`.
- ترفض → `rejected` مع `rejectionReason`.

`pending` و`rejected` لا يظهران في الاكتشاف العام، لكن المالك يراهما ضمن فرقه.

## الانضمام

الفريق المعتمد عام.

1. الضيف يستطيع مشاهدة الفريق.
2. الضغط على Join يطلب تسجيل الدخول إن لزم.
3. المستخدم يوافق على القواعد.
4. ينضم مباشرة.

لا يوجد Request Membership أو انتظار موافقة.

## الأدوار

| الدور | الاستخدام |
|---|---|
| `owner` | منشئ الفريق والمسؤول الأعلى. |
| `admin` | إدارة الفريق والأعضاء حسب الصلاحيات. |
| `moderator` | الإشراف على المحتوى والتفاعل. |
| `member` | عضو عادي. |

الصلاحيات Server-side دائمًا.

## صفحة الفريق

تعرض:

- الاسم والصورة والـcover.
- الوصف.
- التصنيف.
- الموقع.
- المنظمة المرتبطة والتوثيق إن وجد.
- عدد الأعضاء والمنشورات.
- النشاط الأسبوعي.
- القواعد.
- المالك والمشرفين ومعاينة الأعضاء.
- حالة عضوية المستخدم ودوره.

الأقسام:

- المنشورات.
- نبذة.
- مقترح لك.

## المنشورات والتفاعل

الفريق يدعم:

- منشورات.
- تعليقات.
- ردود مستوى واحد.
- Likes للمنشورات.
- Likes للتعليقات.

القراءة العامة مسموحة لفريق `active`، لكن الكتابة والتفاعل تحتاج تسجيل الدخول وعضوية فعالة.

## الإشعارات

الأحداث الأساسية:

- طلب إنشاء فريق جديد.
- الطلب قيد المراجعة.
- الموافقة.
- الرفض مع السبب.
- تغيير دور عضو.
- إزالة عضو.

ويتم استخدام نظام Notifications/FCM نفسه الموجود في JOD.

## التوصيات

التوصيات تعتمد على سياق الفريق مثل:

- التصنيف.
- الموقع.

ويمكن أن تعرض حملات وفرصًا أو فرقًا مشابهة.

## الفرق التطوعية كمنصة تشغيل

المهام والمناوبات ليست نوع فريق جديد. هي Features تضاف لاحقًا إلى نفس `groupId`.

أمثلة:

- مهمة تطوعية.
- فعالية.
- مناوبة.
- سعة مطلوبة.
- مهارات مطلوبة.
- تعيين أعضاء.
- ربط بحملة أو طلب مساعدة.
- سجل مشاركة وإنجاز.

## مراحل التطوير

1. **الأساس:** إنشاء + مراجعة Admin + Discovery + Mine + Detail + Join/Leave + Members.
2. **التفاعل:** Posts + Comments + Likes + Recommendations + Notifications.
3. **الإدارة:** Roles + Remove Member + Edit Team + Reports + Suspension/Audit.
4. **التشغيل التطوعي:** Tasks + Shifts + Assignments + Capacity + Skills + Campaign linking.

هذه مراحل تقنية فقط؛ المستخدم يرى دائمًا منتجًا واحدًا اسمه **الفرق التطوعية**.
